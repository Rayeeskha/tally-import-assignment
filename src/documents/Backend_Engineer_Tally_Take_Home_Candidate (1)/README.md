# Backend Engineer Take-Home: Reliable Tally XML Ingestion

Thank you for taking the time to work on this exercise.

The assignment is based on a real backend problem: ingesting accounting data from an external system whose XML is nested, repetitive, inconsistently encoded, and able to report a business failure even when the HTTP request succeeded.

Prior Tally knowledge is **not required**. Treat the supplied documents and fixtures as the complete contract for this exercise.

## Time Box

Please stop after **6 hours of active work**. Setup, coding, tests, and documentation all count toward the time box. We prefer a correct, well-tested core with honest tradeoffs over a rushed attempt at every extension.

In your project README, include:

- Your approximate active time.
- What is complete and incomplete.
- What you would implement next.
- The production risk created by any missing work.

There is no advantage for spending more than six hours. Optional extensions are not required for a positive result.

## Start Here

Read these files in order:

1. `ASSIGNMENT.md`: scope, priorities, API contract, and scoring.
2. `NORMALIZED_DATA_CONTRACT.md`: required voucher JSON structure.
3. `SUBMISSION_CHECKLIST.md`: final submission check.
4. `fixtures/`: seven sanitized public examples, including byte-encoding cases.
